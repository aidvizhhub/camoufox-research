# Шаблон SKILL.md — как дать агенту память о сервере

> Открытый стандарт **Agent Skills** (agentskills.io); прогрессивное
> раскрытие (microsoft/agent-skills): главное в SKILL.md, детали по
> ссылкам. Скилл = «компетенция агента», а не документ для людей.
> Клади в `<config>/skills/<имя-скилла>/SKILL.md` (у opencode — каталог
> `skills/` в конфиге).

```markdown
---
name: <имя-скилла>
description: >-
  ЧТО даёт скилл (1 абзац) + МАКСИМУМ ТРИГГЕРОВ: слово, действие, файл,
  тул — по которым агент решает «грузить/не грузить». Описание = триггеры.
metadata:
  opencode/autoinvoke: true
---

# <имя-скилла> — краткое

Что это, для чего. 2–4 предложения, без воды.

## Сначала посмотри сюда
- Кто/что: 3–5 строк, самое главное (BLUF — суть первой строкой).

## Рабочие циклы (рецепты)
1. Цикл А: шаг → шаг → шаг (проверенный сценарий, копипаст-пример).
2. Цикл Б: ...

## Границы выбора (КОГДА / НЕ КОГДА)
- Инструмент X — когда структура стабильна; НЕ КОГДА меняется → Y.
- Не делать: ...

## Подводные камни (проверено)
- Кэш/таймаут/гонки — коротко, только проверенное.
- Не долбить: ...

## Пути и вентили (закон 28)
- env-переменные, каталоги, файлы-маркеры. БЕЗ хардкод-путей машины.

## Диагностика (если молчит)
1. `python scripts/mcp_probe.py` — живое рукопожатие/сколько тулов.
2. reconnect через API (НЕ kill); старый код → force-reinstall.
3. Ссылки на полные доки (прогрессивное раскрытие: landmines/docs/*).

## Сценарии (копипаст)
```python
готовый вызов/поток — проверенный, рабочий
```
```

## Чек-лист качества (проф-стандарт, ресёрч 28.08)

- [ ] frontmatter: `name` + богатое `description` с триггерами
- [ ] Суть первой строкой (BLUF); тело ≤ 200 строк
- [ ] Только проверенное (тест на реальном использовании — evaluation-first)
- [ ] Прогрессивное раскрытие: детали по ссылкам, не в теле
- [ ] Примеры-копипаст рабочие
- [ ] Прогнать LLM-валидатором (mgechev: скилл-ревью через модель)
- [ ] Проверить автоинвок: триггер реально срабатывает (флэш-тест)
